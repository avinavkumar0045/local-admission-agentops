# Coding Guidelines

These rules dictate the professional standards for all code generated in this project.

## 1. File Naming
- Use clear, descriptive, accurate, and consistent filenames.
- Use framework/language recommended conventions (e.g., snake_case for Python).
- Avoid vague names (`test`, `temp`, `data`, `helper`).

## 2. Folder Structure
- Maintain a scalable, logically organized folder structure.
- Group related functionality (e.g., `/agent` vs `/agentops`).
- Do not mix unrelated components.

## 3. File Documentation & Comments
- **REQUIRED**: For every file containing more than 2 lines, add a short comment at the top explaining:
  1. What the file is.
  2. Its primary responsibility.
  3. Why it exists.
- Add small, meaningful comments for non-obvious logic, complex algorithms, or important configuration.
- Do not add redundant comments.

## 4. Maintainability First
- Treat everything as a long-term production codebase.
- Ensure new developers can immediately understand the file's purpose and location.

## 5. Consistency
- Follow established conventions strictly.
- **Rule:** Correct location → Correct name → Clear responsibility → Appropriate documentation → Consistent architecture.
